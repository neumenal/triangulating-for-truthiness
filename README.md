# Triangulating for Truthiness
Effective Engagement with LLMs for Software Development and Operations

Author: Jonathan Snyder

Enterprise Technology Leadership Journal: Spring 2026, IT Revolution
https://itrevolution.com/product/enterprise-technology-leadership-journal-spring-2026/

## Summary
Effective problem-solving with an LLM requires prioritizing correctness, clarity, and architectural integrity over raw speed or efficiency. Approaching an LLM with the sole intention of “getting things done faster” is a flawed strategy: It tends to produce superficial fixes, hidden bugs, and misaligned solutions. Focusing first on effective, well-validated solutions helps ensure that any efficiency gains are real, sustainable, and do not compromise system reliability or user experience.

While many of the principles outlined in this paper fall into the category of “systems engineering 101,” it is useful to restate them explicitly in the context of working with LLMs. As LLM adoption becomes more widespread in software development and operations, these fundamentals are easy to overlook or shortcut. This paper focuses on the guardrails required to ensure they remain enforced rather than quietly eroded in the pursuit of efficiency.

The ideas presented in this paper were developed as part of an experiment I conducted around the start of this year (2026) to see what it would be like to work with LLMs to turn a very basic React.js application—the [Parametric Geometry Explorer](https://jaseknighter.github.io/parametric/)—into something more architecturally robust.
